# Realtime Lab Files

Obsidian sync for Markdown, images, PDF, DOCX and supported opaque files. Install through BRAT using `ns19920320-cyber/obsidian-realtime-lab-files`. Each vault requires its own authenticated server space. Keep LiveSync disabled in a vault using this plugin. Existing nonempty uninitialized vaults are not automatically adopted or overwritten.

The Files plugin entry point is `src/v3/plugin.ts`, its manifest is `manifest.v3-files.json`, and its build command is `npm run build:v3-files`. Use the Files build explicitly. `src/plugin.ts`, `build.mjs` and the generic `npm run build` belong to the legacy V2 implementation; do not use them to build Files. Root installation assets can lag an unreleased source branch.

## Development

Use Node.js 22 and `npm ci`, then:

```sh
npm run typecheck
node --test --test-concurrency=1 test/*.test.mjs
npm run build:v3-files
node scripts/check-v3-release.mjs
```

Assets are generated in `work/v3-files-plugin/`. Test with synthetic files and an independent server directory; never point automated tests at an existing vault or server store. Do not commit settings, vault contents, caches, runtime directories or credentials.

## Versions and recovery

`0.5.0-alpha.26` preserves the document and durable queues while reconnecting after foreground wake; offline progress is explicitly stale. The alpha.26 Release `source.zip` is the exact source used for that published build. This repository now contains the editable source; earlier autogenerated tag archives can point to older publication commits. Existing published tags/releases are retained without rewriting history.

See `SOURCE-MAP.md` for source ownership and the release checklist, and `V3-FILES.md` for protocol details. `ARCHITECTURE.md`, `NATIVE-V3.md` and other older documents contain historical milestones; current limits and behavior are defined by the V3 source and tests.

## Desktop background sync

From alpha.37, desktop clients use a native Node timer to check connections and
refresh remote diagnostics about every 10 seconds even when the window is hidden.
Due retries retain their original ledger and versions. Mobile clients still need
the foreground. OS sleep, process suspension and quitting Obsidian stop execution;
no power blocker or background service is installed. Diagnostic reports keep the
real visibility flag; an older server's completion summary may still require the
foreground even when background connection and queue reports are fresh.

## Deleted-name recreation (alpha.46)

Newly created files retain the exact observed deletion generation in the durable pending manifest. A matching alpha.46 server is required to publish these recreations. Older servers leave the local file and cached pending version intact. Concurrent recreation or a newer deletion requires review and does not overwrite another device. Legacy files with no creation evidence are retained under consistency protection. Existing history and caches are preserved.
