# Configuration and secrets

| Name | Used by / scope | Source / rotation | Risk |
|---|---|---|---|
| Vault token | Client settings, authenticated server requests | Existing private token file / settings; rotation remains an explicit existing operation | Vault-wide content access. Never committed, emitted in diagnostic telemetry or included in review archive. |
| serverId / deviceId | Client and server metadata | Existing persisted identities; not reset by this change | Binds job scope; UUIDs are identifiers, not credentials. |
| protectedReview | Client-only persisted job manifest, phase and result | Explicit local action | Contains selected private paths and hashes. Not put into ordinary remote diagnostics. |
| LAB_REVIEW_NAS_ROOT | Server-only review receipt reader | Optional LaunchAgent/environment setting | Enables new capability. Absolute restricted-character directory; never device-controlled. |
| nas SSH alias and key | Server/operator host only | Existing SSH configuration; key rotation outside plugin | NAS access. No key or credential is packaged in plugin assets. |
| LAB_DATA_DIR, LAB_HOST, LAB_PORT, capacity.json | Existing server process | Existing environment / private directory | Routing and bounded storage; deployment must retain existing values. |

No operational secret is bundled into client release assets. A configured client necessarily holds its own vault token in private settings. The release privacy checks reject settings and private environment patterns.

Before enabling: verify NAS reachability and allowed root, snapshot/restore the existing service and plugin settings to NAS, retain old identity/token/capacity, test a synthetic archive, and verify all release hashes. No new NAS credentials are generated by this feature.
